## 밤사이 한 일

### 1. 보안 점검 → 12건 수정
별도 에이전트가 코드를 처음부터 끝까지 점검했어요. 찾은 문제는 모두 코드와 대조해 확인한 뒤 고쳤어요.

| 심각도 | 문제 | 어떻게 고쳤나 |
|---|---|---|
| 높음 | 로그인 후 이동 주소에 탭 문자를 섞으면 피싱 사이트로 보낼 수 있었음 | 주소를 실제로 해석해 보고, 같은 사이트일 때만 이동 |
| 높음 | 결제에 한 번 실패하면 같은 주문으로 다시 결제할 수 없었음 | 중복 결제 방지 기준을 주문이 아니라 결제 건 기준으로 변경 |
| 중간 | 결제 중에 자동 정리가 주문을 취소하면 돈만 빠져나갈 수 있었음 | 주문 상태가 바뀐 걸 알아채면 **결제를 즉시 자동 취소** |
| 중간 | 수정 요청 중에 30일이 지나면 새 영상이 영원히 삭제되지 않았음 | 수정 중인 주문은 자동 삭제에서 빼고, 다시 납품할 때 보관 기간을 새로 잡음 |
| 중간 | 결제 전에 사진 삭제를 누르면 사진 없는 주문이 결제될 수 있었음 | 사진 즉시 삭제는 완성된 주문에서만 가능 |
| 중간 | 새로고침을 여러 번 하면 1~2일 동안 신청이 막혔음 | 결제 대기 주문은 1인 1건. 새로 신청하면 이전 대기 주문을 정리 |
| 중간 | 결제 후 환불·취소 기능이 없어 사진이 계속 남을 수 있었음 | 관리자 **취소·전액 환불** 버튼 추가 (사진·영상·개인정보 함께 삭제) |
| 낮음 | 자동 삭제와 고객 행동이 동시에 일어나면 꼬일 수 있었음 | "먼저 찜하고 지우기" 방식으로 바꾸고, 파일 삭제가 실패하면 되돌려 다음 날 다시 시도 |
| 낮음 | 취소된 주문에 애칭·요청 문구가 남았음 | 취소하면 애칭·자막·요청 내용·연락처를 모두 지움 (결제 기록만 법정 보관) |
| 낮음 | 사진 업로드 재시도 때 늦게 도착한 사진이 섞일 수 있었음 | 업로드가 모두 끝난 뒤에 성공 여부를 판단하고, 사진 수 상한도 확인 |
| 낮음 | 수정본 납품 때 예전 영상을 먼저 지웠음 | DB 갱신이 성공한 뒤에 지우도록 순서 변경 |
| 낮음 | 자동 삭제가 DB 오류를 성공으로 셌음 | 오류를 따로 세고 로그로 남김 |

그 밖에 결제 후 30일이 지나도록 납품하지 않은 주문이 있으면 매일 경고 로그를 남기게 했어요. 결제하지 않은 주문을 정리하는 시점은 결제 중인 사람과 겹치지 않도록 하루에서 이틀로 늘렸어요.

### 2. 자동 테스트 35개 (전부 통과)
`npm test`로 실행해요.
- **결제:** 금액 조작, 남의 주문 결제, 로그인 없이 결제, 토스 응답 금액 불일치, 카드 거절, 새로고침 중복, 취소된 주문, 사진 없는 주문, 승인 도중 주문 취소 시 자동 환불, 재결제 가능 여부
- **자동 삭제:** 비밀값이 없거나 틀리면 거부, 보관 기간이 지난 것만 삭제, 제작·수정 중인 주문은 건드리지 않음, 파일 삭제가 실패하면 다음에 다시 시도
- **기타:** 로그인 후 이동 주소 공격 9가지, 완성 예정일 계산(주말 제외), 템플릿 가격과 길이, Flow 프롬프트 생성

### 3. DB 보안 규칙 실제 검증
로컬 Postgres 16에서 Supabase와 같은 구조를 흉내 내어 마이그레이션을 실행했어요. 확인한 내용은 이래요.
- 사용자는 **자기 주문만** 보여요.
- 금액 수정, 주문 직접 생성, 자기 계정을 관리자로 바꾸기가 모두 **막혀요.**
- 로그인하지 않은 사람은 아무것도 볼 수 없어요.
- 잘못된 전화번호나 상태값은 DB가 거부해요.

검증 스크립트는 `supabase/tests/`에 있어요.

## 확인하지 못한 것 (계정이 필요해서)
- 실제 카카오 로그인, 실제 Supabase 저장소 업로드, 토스페이먼츠 결제창, 알림톡 발송
- 결제와 알림톡은 실제 API 대신 가짜 응답으로만 테스트했어요.

## 아침에 해 주실 일 (순서대로, 약 1시간)

1. **Supabase** ([supabase.com](https://supabase.com))
   - 가입하고 프로젝트를 만들어요. 리전은 **Seoul**로 하세요.
   - SQL Editor에 `dol-film/supabase/migrations/0001_init.sql` 내용을 붙여 넣고 실행해요.
   - Project Settings → API Keys에서 URL, publishable key, secret key를 복사해 둬요.
2. **카카오 개발자센터** ([developers.kakao.com](https://developers.kakao.com))
   - 앱을 만들고 카카오 로그인을 켜요.
   - Redirect URI에 `https://<프로젝트>.supabase.co/auth/v1/callback`을 넣어요.
   - Supabase → Authentication → Providers → Kakao에 REST API 키와 Client Secret을 입력해요.
3. **토스페이먼츠 개발자센터** ([developers.tosspayments.com](https://developers.tosspayments.com))
   - 가입하면 **결제위젯 테스트 키**가 바로 나와요.
4. **Vercel** ([vercel.com](https://vercel.com))
   - GitHub로 가입하고 이 저장소를 가져와요. Root Directory는 **`dol-film`** 이에요.
   - 환경변수 7개를 넣어요. `.env.example`을 참고하세요. `CRON_SECRET`은 아무 긴 무작위 문자열이면 돼요.
5. 배포된 주소에서 **카카오로 로그인**해요. 그다음 Supabase SQL Editor에서 아래를 실행하면 관리자가 돼요.
   ```sql
   update public.profiles set is_admin = true
   where id = (select id from auth.users order by created_at limit 1);
   ```
6. **테스트 결제를 한 바퀴** 돌려 봐요. 신청 → 결제(테스트 카드) → `/admin`에서 영상 업로드 → 공유 → 수정 요청 → 사진 삭제 순서예요.

막히는 화면이 있으면 캡처해서 보여 주세요.
